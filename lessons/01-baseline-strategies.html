RaceBench · Lesson 1

Five answers to one shared-state problem

Two coding agents can each make a locally correct decision and still produce a globally wrong repository. The baseline strategies differ mainly in when they intervene and what unit they treat as shared.

Small taxonomy fix. RaceBench's baseline grid contains six rows: naive is the no-coordination control, followed by five coordination mechanisms—file_lock, git_hash, ast_scope, ast_dep, and notify. [baseline config]

1. The race they are trying to control

Imagine the file begins with only debug. Agent A must add timeout; Agent B must add retries. Both read before either writes.

t₁ · Areads version 0: {debug}
t₂ · Breads the same version 0: {debug}
t₃ · Awrites its locally correct version: {debug, timeout}
t₄ · Bwrites from its stale copy: {debug, retries}. A's correct change silently disappears.

This is a lost update caused by a stale read. “Race” does not mean simultaneous CPU instructions here. It means the final result depends on an unlucky interleaving of long read–reason–write trajectories. RaceBench deliberately reproduces this in t01_stale_clobber.

2. The control: naive

Do nothing beyond atomic writes

control
ReadReturn current disk content.
WriteApply immediately to current disk state.
Conflict responseNone.

The harness serializes each individual file mutation so bytes are not physically interleaved. That is operation atomicity, not coordination across the whole read–reason–write sequence. A full-file overwrite prepared from stale content can still replace a peer's work. [shared apply helper] [implementation]

Why keep it? If agents touch unrelated files—or different functions using safe anchored replacements—coordination adds no correctness and may add delay. The floor reveals whether a fancy mechanism is solving a real race or merely creating overhead.

3. The basic five mechanisms

1 · file_lock

prevent · pessimistic
ReadAcquire ownership of the whole file.
WriteOnly the owner proceeds.
ReleaseWhen that agent finishes.

This assumes collisions are dangerous enough to prevent up front. The first agent to read or write a file owns it until agent_done. Others wait on an asyncio.Condition; after 30 seconds by default, the operation is refused so a wait cycle does not become a silent deadlock. [implementation] [Python synchronization docs]

Saves: stale whole-file clobbers. Costs: two agents editing unrelated functions in one file are serialized. That unnecessary block is a false-positive stall. The protected unit—one entire file—is the strategy's granularity.

2 · git_hash

detect · optimistic
ReadRemember the file content as the base.
WriteCompare base, current, and proposed.
Conflict responseAuto-merge or ask agent to re-read.

This lets agents proceed concurrently because it assumes most edits will not conflict. At write time it performs a three-way merge:

Base
The version this agent read
Current / ours
What is on disk now
Proposed / theirs
The agent's intended result

If current still equals base, the write lands normally. If not, Git tries to incorporate the proposed change into current. Clean combinations land; overlapping hunks return a conflict plus current content so the agent can re-read and retry. Despite the strategy's name, this minimal implementation stores the read content, not merely a hash. [implementation] [Git three-way merge docs] [MegaAgent paper]

Saves: disjoint textual changes often compose without waiting; destructive overlap becomes visible. Costs: text merge understands lines, not program meaning—a clean merge can still be semantically incompatible.

3 · ast_scope

prevent · syntax-aware
ReadRecord every top-level symbol in the file.
WriteDiff old/new syntax trees and claim changed symbols.
Conflict responseWait only on overlapping symbol claims.

An abstract syntax tree (AST) represents code as constructs such as functions and classes rather than raw lines. RaceBench groups top-level functions and classes separately and pools imports/constants/other statements into <module>. Non-Python or invalid Python falls back to <file>. [symbol extraction] [Python AST docs]

So edits to slugify() and truncate() in one file can run together, while two edits to slugify() conflict. Important limitation: syntax proximity is not semantic dependency. Two different functions may depend on the same invariant. Also, a stale full-file overwrite can eventually land after claims are released; symbol locking does not itself merge content.

4 · ast_dep

prevent · dependency-aware
ReadRecord local symbols plus resolved foreign definitions.
WriteCheck symbol claims and cross-file dependency edges.
Conflict responseWait if a changed definition/use overlaps a peer claim.

This starts with ast_scope, then builds a directed graph: use-site → definition, plus the reverse lookup definition → dependents. If Agent A changes a function in models.py while Agent B claims a caller in service.py, the edge can make the race visible even though the files differ. [dependency graph] [implementation]

Saves: some cross-file races missed by same-file symbol claims. Costs: static resolution is best-effort. Dynamic imports, reflection, data/schema relationships, and unresolved names can be missed; an incorrect or incomplete graph produces false negatives.

5 · notify

allow + repair · advisory
ReadRecord the file's top-level symbols in the agent's read set.
WriteLand immediately—never block.
Conflict responseNotify affected active readers before their next model turn.

This accepts temporary inconsistency and delegates repair to the LLM. When a landed write intersects another active agent's earlier read set, a notice tells that reader to re-read if relevant. The message is injected before its next model call. [implementation] [delivery point]

RaceBench intentionally implements CoAgent-lite: only notification plus agent self-judgment. It omits CoAgent's fixed serialization order, inverse operations, and mechanical reordering, so it does not inherit the full protocol's guarantees. [CoAgent paper]

Saves: no waiting; a capable agent can repair a stale plan. Costs: the notice may arrive after damage, may be irrelevant, or may be ignored/misunderstood. Reading one file records all its top-level symbols, so notices can also be conservative.

4. The comparison that matters

StrategyIntervenesUnit of reasoningCore betCharacteristic failure
naiveNeverOne atomic mutationEdits will compose naturallySilent lost update

git_hashAt writeTextual three-way diffMost concurrent edits mergeClean text merge, broken semantics
ast_scopeAt writeTop-level symbolSyntax approximates independenceCross-symbol semantic race
ast_depAt writeSymbol + static dependency edgeStatic references approximate impactUnresolved/dynamic dependency
notifyAfter writeRead/write-set intersectionThe LLM can judge and self-repairLate, ignored, or noisy notice
The research question is not “which row wins?” It is: for a particular failure mode, does the safety gained justify waiting, token cost, wasted work, and false-positive stalls? RaceBench keeps tasks and the agent loop fixed so the mechanism is the changing variable. [submission write-up]
